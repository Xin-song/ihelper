## 0. 术语表

先统一叫法，避免文档和代码里同一个东西有三个名字。

| 术语 | 含义 | 代码中的名字 |
|---|---|---|
| 空间 Space | 数据归属单位，Phase 3 前恒等于「我一个人」 | `space` |
| 用户 User | 登录账号 | `user` |
| 食材 Ingredient | 可被菜谱引用的原料主数据 | `ingredient` |
| 菜谱 Recipe | 一道菜的完整做法 | `recipe` |
| 配料项 RecipeIngredient | 菜谱与食材的关联，带用量 | `recipe_ingredient` |
| 库存条目 StockItem | 家里实际存有的某物品及其数量 | `stock_item` |
| 耐用品 Asset | 不会被消耗的家庭物品（家电、家具） | `asset` |
| 待办 Task | 需要做的一件事 | `task` |
| 记录 Post | 一条生活记录 | `post` |

## 1. 菜谱模块 【MVP · Phase 1】

这是第一版唯一要做完做透的模块。

### 1.1 食材主数据 — P0

菜谱不能直接写「两个鸡蛋」这种自由文本，否则库存联动和购物清单合并全都做不了。食材必须是独立实体。

- 字段：名称、别名（「土豆/马铃薯/洋芋」应指向同一条）、分类（蔬菜/肉禽/水产/调味/主食/干货/其他）、默认单位、备注
- 录入菜谱时若食材不存在，支持**行内快速创建**，不打断录入流程
- 别名支持模糊匹配搜索
- 允许合并两条重复食材（把引用关系一并迁移）

### 1.2 单位与换算 — P0

这里是最容易过度设计的地方，划清边界：

- **必须支持**：质量（g / kg / 斤）、体积（ml / L）、计数（个 / 只 / 根 / 片）
- **必须支持**：厨房常用近似单位（勺 / 汤匙 / 茶匙 / 杯），按固定近似值换算即可，不追求精确
- **必须支持**：模糊用量（适量 / 少许 / 按口味）—— 存为特殊标记而非数字，缩放时原样保留，购物清单里单独列出不参与合并
- **不做**：食材密度表（同样体积的面粉和水质量不同）。跨量纲换算（ml ↔ g）在第一版直接不支持，超出必要复杂度

### 1.3 菜谱 CRUD — P0

- 基本信息：标题、封面图、简介、分类、标签（多选，自由创建）
- 元数据：准备时长、烹饪时长、难度（1–5）、基准份数
- 配料表：食材 + 用量 + 单位 + 可选备注（「切丁」「提前泡发」），可排序，可标记为「可选配料」
- 步骤：有序列表，每步文字 + 可选配图 + 可选计时提示
- 附加：来源（链接/书名/「奶奶教的」）、个人评分、最近制作时间
- 软删除，误删可恢复

### 1.4 分量缩放 — P0

- 输入目标份数，配料用量按比例换算
- 结果做**智能取整**：`1.33 个鸡蛋` 显示为 `约 1½ 个`，而不是刺眼的小数
- 模糊用量不参与缩放
- 缩放是纯展示行为，不修改原始数据

### 1.5 搜索与筛选 — P0

- 关键词搜全文（标题、简介、步骤）
- 按分类、标签、难度、总耗时筛选
- **食材反查**：「冰箱里有鸡蛋和番茄，能做什么」—— 这是高频真实场景，必须做
- 排序：最近添加 / 最近制作 / 评分 / 耗时

### 1.6 购物清单 — P0

- 多选菜谱（可各自指定份数）→ 生成清单
- **同食材自动合并**，同量纲单位自动统一（3 个鸡蛋 + 2 个鸡蛋 = 5 个鸡蛋）
- 按食材分类分组显示，方便按超市货架动线采购
- 可勾选、可手动增删条目
- 导出为纯文本，方便发到微信/备忘录
- Phase 2 接入库存后：扣除家里已有的量，只列真正需要买的

### 1.7 做饭模式 — P0

手机在厨房台面上、手上沾着水时用的界面，与桌面浏览体验是两套需求。

- 大字号，高对比度
- 步骤逐条推进，当前步骤占满屏幕
- 配料表可随时唤出对照
- 保持屏幕常亮（Wake Lock API）
- 步骤内的时间可点击启动计时器
- 已完成步骤可打勾，防止走神后忘了做到哪

### 1.8 菜谱模块 P1/P2

- P1：菜谱导入导出（JSON）
- P1：营养信息（热量、蛋白/脂肪/碳水），手工填写即可
- P2：从常见菜谱网站解析导入
- P2：周菜单规划（把菜谱排到日历上）
- P3：按现有库存推荐今天能做什么

## 2. 库存模块 【Phase 2】

### 2.1 消耗品库存 — P1

- 字段：关联食材/物品、当前数量、单位、存放位置（冰箱冷藏/冷冻/储物柜/…）、保质期、低库存阈值、备注
- 出入库记录：每次增减留痕，可追溯
- **低库存提醒**：低于阈值时自动生成采购待办
- **临期提醒**：保质期临近时提醒，避免浪费
- 快速盘点界面：一屏批量调整数量

> **2026-08-01 提前做了最小版**（详见 ARCHITECTURE.md 4.4、DATABASE.md）：分类（复用食材分类）、
> 当前数量、单位、备注、安全库存阈值，登录后 `/inventory` 页面管理，+/− 按钮调整数量。
> 低于安全库存的物品在页面里的「采购清单」标签页自动列出（纯派生视图，不是持久化的待办）。
> **还没做**：物品和食材主数据的关联（现在是自由文本名称，不是 `ingredient_id` 外键）、
> 存放位置、保质期、出入库流水记录、临期提醒、接入待办模块生成真正的采购待办、快速盘点界面。

### 2.2 菜谱联动扣减 — P1

- 菜谱页面点击「已做这道菜」→ 按配料表和实际份数扣减对应库存
- 扣减前弹出确认，允许逐项调整（实际用量常与菜谱不同）
- 库存不足时提示但不阻断
- 同时记录一次「制作历史」，更新菜谱的最近制作时间

### 2.3 耐用品台账 — P2

- 字段：名称、分类、品牌型号、购入日期、价格、购买渠道、保修截止、存放位置、状态（在用/闲置/已弃）
- 附件：发票、说明书、保修卡（图片或 PDF）
- 保修到期前提醒
- 简单统计：按分类看资产分布、总价值、平均使用年限

## 3. 待办与日程模块 【Phase 2】

### 3.1 待办 — P1

- 字段：标题、描述、截止时间、优先级、标签、所属项目/清单、状态
- 子任务（一层嵌套即可，不做无限层级）
- 重复规则：每天/每周 N/每月 N 号/每年，以及「完成后 N 天再来」
- 来源标记：手动创建 vs 系统生成（如低库存自动生成），系统生成的可一键跳回来源

> **2026-08-02 提前做了最小版**（详见 DATABASE.md 第 8 节）：标题、描述、截止时间、优先级、
> 状态（含「进行中」，覆盖「正在进行的工作」这个场景）、标签；额外做了一个「看板」视图
> （进行中 + 未来三天按优先级排序，不在原始需求清单里，是补充需求）。
> **还没做**：子任务、重复规则、系统生成待办的来源标记与跳回。

### 3.2 日程 — P1

- 日/周/月三种视图
- 待办按截止时间落在日历上
- 支持纯日程事件（有起止时间、无完成状态，如「牙医预约」）
- 全天事件、跨天事件
- P2：iCal 订阅导出，可被系统日历读取

> **2026-08-02 提前做了最小版**：日/周/月视图、待办按截止时间落在日历上、纯日程事件、全天事件都已做。
> 额外做了美国联邦假日标注（按 5 U.S.C. § 6103 规则本地计算，不接外部日历 API，不在原始需求清单里）。
> **还没做**：跨天事件在周/日视图的展示（月视图已支持，agenda 列表按「当天是否被覆盖」判断，
> 没有做真正的跨天横条）、iCal 订阅导出。

### 3.3 提醒 — P2

- 站内通知（第一版够用）
- P2：浏览器推送（Web Push）
- P3：邮件 / 移动端推送

## 4. 家庭空间与协作 【Phase 3】

### 4.1 空间与成员 — P1

- 一个用户可属于多个空间（自己的 + 家庭的），顶部切换
- 邀请码或邮件邀请加入
- 角色：管理员（增删成员、改设置）/ 成员（读写业务数据）/ 只读（如老人、小孩账号）

### 4.2 数据可见性 — P1

- 每条数据有归属：个人私有 / 空间共享
- 默认值可按模块配置（如菜谱默认共享，待办默认私有）
- 私有数据管理员也不可见 —— 这一点必须成立，否则家人不会放心用

### 4.3 家庭事项 — P2

- 可指派给成员，多人协作
- 值日轮换类事项：按周期在成员间自动轮转
- 进度对所有成员可见
- 操作审计：谁在什么时候改了什么

## 6. 全局非功能需求

### 6.1 平台与兼容

- 第一版仅 Web，但**移动端浏览器是一等公民**，不是「顺便适配一下」。做饭模式、盘点、记账式的快速录入，主战场都在手机
- 目标浏览器：最近两个大版本的 Chrome / Safari / Edge / Firefox
- Phase 5 起提供 PWA，可添加到主屏

### 6.2 性能

- 本地部署（10 用户以内）：常规页面首屏 < 1s
- 云端（1000+ 用户）：API P95 < 300ms
- 菜谱列表分页或虚拟滚动，不一次性拉全量

### 6.3 数据安全

- 密码使用 Argon2 或 bcrypt 哈希，绝不明文
- 全站 HTTPS（云端部署）
- 上传文件校验类型与大小，图片剥离 EXIF 中的 GPS 信息
- 所有查询参数化，杜绝 SQL 注入
- 敏感操作有速率限制

### 6.4 数据主权 — 这是产品承诺，不是可选项

- 随时一键导出全部数据为 JSON
- 导出数据可完整导入回一个空实例
- 提供数据库备份脚本与恢复文档
- 永远提供可自建的开源版本

### 6.5 国际化

- 第一版仅简体中文
- 但**文案不硬编码在组件里**，统一走 i18n 文件，为将来留门
- 时间统一以 UTC 存储，按用户时区展示

### 6.6 可访问性

- 语义化 HTML，表单有 label
- 键盘可完整操作
- 对比度符合 WCAG AA
- 做饭模式特别照顾大字与易点击

## 7. 需求变更流程

1. 新想法先记到本文档的 **P3 想法池**，不要直接开做
2. 每个 Phase 启动前，回顾一次 P1/P2/P3，重新排优先级
3. 优先级调整必须同步更新 ROADMAP.md
4. 已完成的需求在条目前打 `[x]`，不删除 —— 保留历史便于回顾
